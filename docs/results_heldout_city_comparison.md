# Held-out-city model comparison

Generated by [`train/compare_heldout_cities.py`](../train/compare_heldout_cities.py) from the committed fold results in `results/runs/p3_topology/`.

## What is being compared, and on which cities

The 10 OSCD **test** cities have **not been scored** in this project — their labels are published separately by OSCD and were never downloaded or used here, so the only output for them is a predicted mask per city. Evaluating them is outstanding work (see [`hidden_city_evaluation.md`](hidden_city_evaluation.md)). Every metric below is therefore on a **held-out city** from the labelled set: 5-fold city-grouped CV over the 14 labelled cities, each held out exactly once and scored by a model trained without it.

The comparison is paired — identical fold assignment, identical initialisation and identical training patch stream across models, so the circuit is the only difference and per-city differences are matched pairs.

![the 24-city split](../results/p3_matrix/city_split.png)

![held-out city comparison](../results/p3_matrix/heldout_city_comparison.png)

Both figures come from the same fold records as the tables below (`python train/plot_heldout_comparison.py`).

Primary metric here: **AP**. Chance level for AP is the city's own prevalence (~2.3 % overall), so AP values must be read against that column.

## Reading guide

- **Per-city win counts are the honest unit here, not the macro mean.** 14 cities come from 5 trained models per cell, so cities inside a fold share a model and are not independent samples. No p-values are computed.

- F1 in the per-city tables uses a **per-city** threshold swept on the very pixels it scores — an optimistic best-operating-point diagnostic, not a deployment number. The deployment operating point is the single frozen τ\* = 0.5808 from pooled out-of-fold predictions.

- A model winning on macro AP while losing on several cities is a domain-shift result, not an architecture result. Finding 3 in the poster says exactly this.
